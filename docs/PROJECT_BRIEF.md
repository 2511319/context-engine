# Context Engine — краткий бриф

## Что это
Сервис-помощник для языковой модели: даёт целевой контекст из большой кодовой/доковой базы, чтобы экономить окно и поддерживать понимание проекта при решении задач. По запросу ИИ получает релевантные фрагменты кода, документов и структурные связи из графа знаний.

## Зачем
- Сократить токены: подгружать только нужные куски, а не весь репозиторий.
- Сохранить связность знаний: ИИ видит, как связаны файлы, модули, секции документации, символы, тесты.
- Ускорить работу: быстрый поиск по эмбеддингам + переходы по графу (REFERENCES, USES, TESTS и т.д.).

## Как работает (практически)
1) Индексация репозитория
   - Берём список файлов из `git ls-files` (игнорируем мусорные/сервисные пути).
   - Режем код и доки на куски, считаем эмбеддинги (OpenAI), пишем в Postgres.
   - Парсим Python-символы, фиксируем связи (определён в файле, использует импорт, описан в доках, покрыт тестами).
   - Доковые ссылки и текстовые упоминания превращаем в `REFERENCES`.
   - SIMILAR_TO строим на эмбеддингах для доков/файлов (быстрые “мостики” по смыслу).
   - `--prune` удаляет всё, что пропало из git, чтобы не было фантомов.

2) Проекция в граф (Neo4j)
   - Узлы: Doc, DocSection, File, Module, Symbol, Tool/Database (если есть).
   - Рёбра: HAS_SECTION, PART_OF_MODULE, DEFINED_IN, USES, TESTS, REFERENCES, SIMILAR_TO.
   - Все рёбра помечены `project`, чтобы фильтровать по проекту.

3) Ответ на запрос
   - По задаче подбираем релевантные куски (эмбеддинги) и дополняем их окрестностью из графа (секции, связанные файлы/символы, похожие документы, тесты).
   - Результат отдаем языковой модели как компактный контекст.

## Что уже настроено
- Жёсткая очистка: при parse-fail символы/связи файла удаляются; при `--prune` сносятся записи вне git.
- Авто-ссылки: markdown ссылки, упоминания .py, модулей и (консервативно) имён символов.
- Тестовые связи: файл тестов → модуль (по пути) и → символы, если есть вызовы.
- SIMILAR_TO для Doc/File (top-k=6, порог 0.8) для быстрой смысловой навигации.

## Остаточные особенности
- Есть “тихий” код (около 250 Symbols без связей): парсятся, но на них нет импортов/тестов/ссылок. В эмбед-поиске доступны, в графовом обходе не расширяют контекст. При необходимости можно добавлять связи (imports/test refs/SIMILAR_TO для Symbol).
- Листовые узлы (одна связь) для Doc/File/Symbol — нормальны: это либо конечные секции, либо одиночные файлы/символы без вызовов.

## Как пользоваться
- Для обновления данных: `index_repo.py --project mimic_codex --repo-root <repo> --prune`, затем `build_similarity.py`, затем `graphify.py`.
- Для получения контекста в коде/CLI — вызывать инструменты MCP (get_context/search_raw/graphify и т.д.) через настроенный сервер `context_engine`.

## Цель качества
Давать языковой модели минимальный, но достаточный контекст: релевантные куски + осмысленные связи, без перетаскивания всего репозитория и без накопления старых данных.***
